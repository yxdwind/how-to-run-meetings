# evals/ —— 基准评测（改 skill 后跑回归）

> 用途：证明「这个 skill 真的让办会输出变好了」。每次改动 workflow.md / templates/ / rubrics/ 后跑一轮，与基线对比，防退化。

## 方法

1. **任务**：从 [briefs/](briefs/) 取任务简报，同一简报跑两遍——**带 skill**（按 [workflow.md](../workflow.md) 五步工序，可读仓库全部技能文件）与**不带 skill**（直接让模型办会，禁止读取任何技能文件）。
2. **盲评**：两份产出去掉标识、命名为「卷A/卷B」，交审阅方（人或独立 agent）按 [scoring.md](scoring.md) 打分；对照关系只记录在 `runs/blind/_key.json`。
3. **硬指标先行**：评分表中可直接数、可直接查的项（必要性作答、议程程序、时限刚性、溯源、筛项通过数）机器可判，占 60%；软评（场景口吻、可用度）占 40%。
4. **记录**：每轮结果追加到 [runs.log.md](runs.log.md)，含日期、commit、总分、逐维分、失败项。

## 匿名化执行清单（每轮必做，2026-10-12 审计后增）

首轮/二轮评审时卷面残留了身份标注（标题「带 skill 卷/基线卷」、执行说明、仓库内链接）且未洗牌——「盲评」名不副实，详见 [runs.log.md](runs.log.md) 完整性注记与 [AUDIT_V1.1.md](../AUDIT_V1.1.md) P1-1。自下一轮起严格执行：

1. 复制参评卷后**删除标题中的身份词**（改为「卷甲/卷乙」），删去「执行说明」整段引文与任何自述身份的句子；
2. 删除指向仓库内文件的链接（如 `[workflow.md](../../workflow.md)`）与 skill 内部编号以外的可识别引用；
3. 卷名与身份的对应**洗牌**（不得卷A恒为基线），对照表只写入 `runs/blind/_key.json`；
4. 评审提示词明示两条约束：「评审方禁止读取本仓库技能文件（workflow/templates/rubrics/chapters）」与「卷面不应含身份信息，若发现残余标注请忽略并报告」。

> 历史处置：已有盲评卷与评审档案为历史记录，保持原貌不改；分数方向经复算不依赖身份假设（见 AUDIT_V1.1.md P1-1 影响分析）。

## 判定

- **有效**：带 skill 总分 ≥ 基线 + 10%，且硬指标无一项退化。
- **回归**：已通过的简报在新版本下掉档 → 改动引入退化，先修再发。

## 目录

```
evals/
├── README.md      # 本文件
├── scoring.md     # 评分表（维度+分值+判分规则）
├── briefs/        # 任务简报（输入，不随版本改）
├── runs/          # 参评卷存档：skill-bX.md（带 skill）/ baseline-bX.md（基线）
└── runs.log.md    # 每轮跑分记录（runs/blind/ 内为匿名卷+评审档案+对照密钥）
```

## 约束

- 简报里的素材（任务清单/数据/人事安排）视为"用户提供的材料"——按工序红线，产出必须溯源到这些材料，不得外加编造。
- 评测不联网补料，保证两遍（带/不带 skill）输入一致。
- 软评存在 AI 评审偏置：双人盲评时交换顺序各评一遍，分差 >15% 的维度标记人工复核。

## 与 how-to-write 评测层的分工

how-to-write 的评测考察**成文质量**（字数、口吻、引文溯源）；本层考察**办会判断**（类型选择、议程程序、民主集中、落实载体）。讲话稿成文任务的评测归 how-to-write/evals，不在此重复。
