# 决策会程序模板（decision-procedure）

> 用途：会中执行第③步决策线的标准程序（ch07）。决策正确则会议正确，决策失误则会议根本失误。
> 标注说明：出处为第七讲（含第三、六讲衔接）；程序卡为本 skill 工程增设【增】。

## 会前：议题成熟度检查（上会前走完程序）

```
议题：＿＿＿＿＿＿
提出部门：＿＿＿＿  分管/主要领导：已同意 □  职能部门：已逐项审核协调 □
调研沟通：□已充分（基本情况理出头绪、主要问题搞实搞准）
议题四种可能预判（ch07）：□完全同意（少见） □补充修改后通过（争取的最常见结果）
                          □否定后另作决策 □否决且不作决策（议题确有大缺陷就不勉强）
```

硬伤软肋不上会；临时动议不上会——程序错误往往伴随实质内容错误（ch07）。

## 三个规矩（会上逐条守，ch07）

| 规矩 | 操作 | 自查 |
|------|------|------|
| 既定权力界限 | 决策权来自谁就向谁负责，不得越权越界，权责一致 | □ |
| 集体审议决策 | 严密规则限制个别人专权擅权，一把手不主观武断 | □ |
| 少数服从多数 | 表决前保证每位成员充分发表意见，少数人意见也要尊重 | □ |

民主集中三步骤：把主张亮出来 → 充分听取意见 → 该定的必须有权威说法，原则问题不动摇（ch03）。

## 难题加菜：头脑风暴（难点无现成答案时，ch07）

- 前提：问题先定准；会前个别沟通交流（不许会上突然袭击）。
- 会上：包容明显对立的意见，从极端意见中捕捉破局思路——不断掉旧路径，就改变不了旧习惯。

## 决策记录（会议纪要的素材，ch06/ch07）

```
议题：＿＿＿＿＿＿
讨论意见：赞成的（要点）＿＿＿＿；反对的（要点）＿＿＿＿；模棱两可的（研判）＿＿＿＿
决定：＿＿＿＿＿＿（权威说法，不含糊）
表决：同意__人 / 反对__人 / 弃权__人（如需）
落实载体：责任主体＿＿｜事项/项目＿＿｜刚性时限＿＿年__月__日前    ← 缺一项即回炉（ch15）
跟踪评估：下次检查时点＿＿（决策后系统跟踪，发现不科学不周全及时调整修正，ch07）
```

## 紧急决策变体（火烧眉毛的事，ch07）

先处置险情（如先撤离群众）→ 短平快头脑风暴（一小时边听边问边梳理）→ 果断拍板；紧急决策也要先集成干部与专家两类信息再定。
